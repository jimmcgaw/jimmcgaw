I love AI because I love learning new things, and especially learning practical things, that I can apply to my own life and work right away.

## About my GitHub: Write One to Throw Away

In practice, I follow Fred Brooks's advice, often paraphrased as "Write one to throw away". I create a lot of repos on GitHub, to try new frameworks, languages, databases, build configurations, and so on.

That is, I create a lot of public repos to experiment, and to "learn out loud" for anyone else who might be watching. I try (but usually fail) to adequately document what I'm doing, or intend to do, in the README.md for each repo.

At some point, I usually hit a critical mass of comprehension (the "light bulb moment") with the new thing I'm playing with. I then start integrating that new thing into a project I'm doing, which I usually keep in private repos.

## Let's Talk About AI for Software Engineering

In short, my philosophy about AI, and how I use it to assist me as an engineer, is well-summarized in a old Ross Perot quote about leadership: _"Never ask anyone to do what you haven't done before and wouldn't do again"_, but `s/anyone/ai/g`.

### Writing Project Code

I currently use Google's Antigravity IDE to configure projects and write code for me. It is the bees knees, not because I can do things I couldn't do before, but because it does things I used to do much faster. 

Much more critically, when I ask it to troubleshoot an issue, it shows me its work, which often empowers me to understand how best to troubleshoot that issue myself.

Another way to put is leans on Joel Spolsky's post about<a href="https://www.joelonsoftware.com/2002/11/11/the-law-of-leaky-abstractions/" target="_blank">"The Law of Leaky Abstractions"</a>. Basically, _AI is a leaky abstraction_. *The responsible use of AI for building software systems involves your own comprehension of at least one or two abstraction layers below the level at which the AI is operating.*

I know how to write code. I know the principles behind architecting systems of networked docker images. I know how to drop into a shell and run commands to debug errors. AI does a lot of this faster than I could do it myself, and autonomously. 

### Beyond the Code

AI has been most useful to my education as a engineer in helping me plan out how governance, policy-as-code, and best security practices should be applied, using various frameworks tailored, to specific situations.

As one small example, I learned the MAESTRO framework, and how to apply it to one of my own agentics AI systems, from AI. 

### Governance via PolicyOps

In college, I learned the principles of auditing systems, based on frequentist statistics, which entails sampling, analyzing the sample, and hoping that your sample is representative of the broader population. This is both reactive and partial. I'm excited that in the coming years, transactional systems, leveraging PolicyOps, will be enabled to audit pending transactions and allow / reject them based on policy-as-code in real-time.

Get in touch if you want to talk about how new AI regulations and legislation can be translated into auditable, reviewable policy code that can be used to govern how AI systems behave in production.
